## Implementation notes

- Schema: `projects` collection in `src/content.config.ts` — entry id generated from frontmatter `slug` (stable join key; duplicates fail the build at load), closed `kinds` enum (min 1), month-precision `started`/`ended` (YYYY-MM, `ended` nullish = ongoing, refine guards ended ≥ started), `status` enum, separate `draft` flag, open `tech[]`, `links[]` of {platform, url}, `screenshots[]` max 4 with required alt, `featured`.
- Shared `LsFilterRow.astro` component (`ls <dir> --flag` row vocabulary for later listings): client-side filtering over rows carrying `data-filter-values`, live count, dry empty error (`ls: no matches for --kind X`) with a real command-link reset, deep links via `?kind=` (history.replaceState).
- Listing `src/pages/projects/` : unboxed rows (cyan `slug/`, dim ellipsized summary, right-aligned pink kind · amber tech · status-dates), hover screenshot pop (`slug.png · 1/N`, first screenshot; shows on row hover and on row-link keyboard focus, hidden on mobile), rows sorted `started` desc, drafts excluded.
- Detail `src/pages/projects/[slug].astro`: README window (titlebar `<slug>/README.md · rendered`, rendered markdown with `## `-prefixed amber sections, inline screenshot figures) + sticky neofetch sidebar (`$ identify <slug>` above bare datasheet box; pink reserved for dates only; cyan ↗ links) + reserved related-studies area (`# related studies` heading + `# no linked studies yet` empty comment — ticket 25 queries studies by `projects[]` into this seam; list styles already in `detail.module.css`).
- Chrome copy in `src/lib/constants.ts` under `PROJECTS`; placeholder screenshots generated by a throwaway sharp script (gradients + label), real content replaces them in ticket 32.
- Verified: build fails on bad `kinds` value and on empty screenshot `alt`; draft entry (`sidequest`) excluded from listing and detail paths; both themes render (tokens flip).

## Comments

- Code review (two-axis) ran on the work; two findings fixed (empty-error template now flows from `PROJECTS.emptyPrefix` instead of a hardcoded string in the filter component; note wording). Two judgement calls kept as prototype-approved (ticket 17 variant D) and flagged here for Mayur:
  1. **Pink kind / filter-active / hover-slug in the listing** — ticket 22's "pink stays reserved for dates/errors/failures" parenthetical is attached to the *detail* page (where pink appears only on dates); the listing colors come straight from the approved variant D prototype (pink kind, pink active filter, pink hover slug). If the reservation should be sitewide, the listing kind should go dim/ink — one-line change in `listing.module.css`.
