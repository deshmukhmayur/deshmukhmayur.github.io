# Map: Personal site rebuild (portfolio + playground)

Label: wayfinder:map

## Destination

A fully rebuilt personal website for Mayur Deshmukh at deshmukhmayur.com, hosted on Cloudflare as a static site, replacing the existing GitHub Pages page. The site is a personal playground that showcases portfolio/work, anime-style art, 3D printing, a Soliloquy/Studies writing area, and an about page with resume download — supported by a contact form and self-hosted Umami analytics. Done = a spec + working deployed site (spec synthesized from this map, then implemented).

## Notes

- Repo currently holds a small static page (index.html + css/ + img/), full replacement planned. Domain deshmukhmayur.com.
- Decisions already settled during charting (standing for all tickets):
  - **Stack: Astro** (user knows both Astro and Eleventy; Astro wins on component model, image optimization, content collections).
  - **Hosting: Cloudflare Workers with static assets** (not Pages), plus Workers for form/analytics; deshmukhmayur.com on Cloudflare.
  - **Persona: "personal playground"**, not employer-first; portfolio is a section, not the whole page.
  - **Projects section** (renamed from "Work" per Mayur; kinds vocabulary `work`/`open-source`/`personal` unchanged): programming/open-source/personal projects, detail pages with screenshots/tech stack/metadata; content model decided (ticket 11) — case studies are Studies cross-linked via `projects[]`.
  - **Writing umbrella**: two content types — casual entries = **Soliloquy**, substantive write-ups (case studies, findings, experiments) = **Studies**, visually distinct listings.
  - **Art section**: curated gallery grid + detail pages; content collections with tags/collections; detail page shows related artworks from same collection, falling back to related tags. Content spans anime-style illustrations, sketches/doodles, and car sketches — taxonomy must accommodate all three (ticket 04).
  - **Prints section**: gallery with print specs (printer, material, settings), detail pages including a build/maker log, external links to model pages (Printables/Thingiverse/MakerWorld).
  - **About/resume**: simple about page with a download-resume button (no structured-data resume rendering for now).
  - **Contact form**: tiny Cloudflare Worker with Turnstile spam protection; simple storage (KV/D1) or email send.
  - **Analytics: Cloudflare Web Analytics** — decided in ticket 08; manual beacon in layout, `/resume/` download page for download counts.
  - **Visual direction instincts**: minimal, light palette, light/dark theme toggle, illustrations/icons used playfully where they feel good, occasional playfulness. To be prototyped before commit.
- Skills: prototype tickets load `prototype` + `frontend-design`; `research` skill for research tickets.
- Content gathering is part of this effort; structure first, then content.

## Decisions so far

- [Prototype: Homepage look and feel](issues/03-prototype-homepage-look.md): Winner = terminal/TUI variant F — full-bleed dark terminal, neofetch-style about header (own illustration + whoami + now→employer line), panes (work+skills, art+prints, studies+soliloquy) with social links top-right inside their relevant pane, soliloquy-of-the-day line, ASCII-cat footer, light/dark toggle. Prototype: `prototype/homepage-prototype.html` on branch `prototype/homepage-look`.
- [Research: Cloudflare static hosting](issues/01-research-cloudflare-hosting.md): Workers static assets works with a minimal `wrangler.jsonc` (no adapter); free-tier static requests unlimited; 20k files/version, 25 MiB/file limits; use `404-page` not SPA fallback; custom domain via `routes` + separate www redirect; CI via `wrangler-action@v3` or Workers Builds.
- [Research: Umami on Cloudflare](issues/02-research-umami-on-cloudflare.md): No official Umami Workers/D1 path — it's Node/Postgres; better fits are Cloudflare Web Analytics (free, trivial) or GoatCounter (free non-commercial, easy self-host); analytics tool choice moved to a grilling ticket.
- [Grilling: Art section content model](issues/04-art-content-model.md): Two-axis taxonomy (optional `collection` + closed-list subject tags; `medium` as structured field, not tag); publish-ready-only entries with `featured` flag for 3–4 homepage slots; unified masonry grid with tag filters, tiles go straight to detail; URLs `/art/<YYYY-MM-DD>-<slug>/`; detail page has title/date/collection/tags/medium/tools/description + process shots, related works (same collection → same tags → hide); repo-committed originals via astro:assets, required `alt`.
- [Task: Art image import & compression pipeline](issues/13-task-art-image-import-pipeline.md): Astro 5 scaffolded at repo root; `scripts/import-art.mjs` strips EXIF + mozjpeg q82 + 4096px cap and scaffolds entries; EXIF stripped at import (build still emits unreferenced originals); `<Picture>` avif/webp/jpg at 480/960/1600; required-alt enforced by schema; trial entry validated end-to-end.
- [Prototype: Art gallery grid + detail page](issues/14-prototype-art-gallery-detail.md): Gallery = windowed masonry (terminal-window tiles: filename + date titlebar, caption `collection · medium · #tags` with wrapping tag runs, `$ ls art --tag` filter row). Detail = console-output style (full-width image, `$ identify` metadata block, `process/` thumbnails, related-works row). Terminal voice stays in frames/captions; art fills unframed space. Prototype: `prototype/art-gallery-prototype.html` on branch `prototype/homepage-look`.
- [Grilling: Prints section content model](issues/05-prints-content-model.md): Schema = title, date, printer, material, durationHours, photos (astro:assets + required alt), description, `modelLinks[]` of `{platform, url}` (own designs included once uploaded), tags, `featured` flag (homepage pane pulls 2–3); print settings stay freeform in body markdown. Maker log = dated markdown sections in the entry body; failures only as attempts inside a successful print's log. Shares terminal-window tile vocabulary with art, separate collection/URLs (`/prints/<YYYY-MM-DD>-<slug>/`). Listing UI → contact-sheet prototype (ticket 15).
- [Grilling: Soliloquy / Studies content model](issues/06-soliloquy-studies-model.md): Soliloquy = `title?`, `datetime`, `slug?` (titleless → date+ordinal URL), `tags[]`, images via markdown body only, micro entries allowed; Studies = `title`, `date`, `summary`, `tags[]`, `featured`, `status`, `projects[]` — many-to-many edge to Work slugs (work pages query Studies by slug, validation once Work model lands). Open tag vocabulary shared across both; chronological spine + per-type tag-filter row; URLs `/soliloquy/<slug>/`, `/studies/<slug>/`; listing look → prototype (ticket 16).
- [Grilling: Contact form specifics](issues/07-contact-form.md): D1 storage; Resend free-tier email notification on submit; Turnstile + one WAF rate-limit rule, no custom counters; fields = name/email/message + hidden honeypot; plain reply-to-email (one-shot inbox, no site-hosted threads); terminal-flavored inline success/error in the contact pane, no redirect.
- [Grilling: Analytics tool choice + provisioning](issues/08-setup-umami.md): Cloudflare Web Analytics (not Umami/GoatCounter — a VPS just for analytics doesn't fit the zero-ops Cloudflare-only stack). Pageview paths give per-section traffic; resume downloads counted via a `/resume/` HTML download page (bare PDF link wouldn't be counted); manual beacon snippet in Astro layout head; token as env/config value; provisioning checklist runs at deploy time.
- [Grilling: Work/projects section content model](issues/11-work-content-model.md): Schema = title, stable slug (join key for Studies' `projects[]`), summary, `kinds[]` closed multi-select (`work`/`open-source`/`personal`; employer-OSS-upstream checks both), started/ended (month precision), `status: active|maintained|archived` + separate `draft` flag, optional role, open `tech[]`, `links[]` of `{platform,url}`, 1–4 screenshots (required alt), `featured` (homepage pane pulls 2–3); body = overview only. Case studies are Studies cross-linked via `projects[]` — no new type, no duplication. Listing = flat `/projects/` (section renamed from Work), started-desc, kind filter row, screenshot-led terminal tiles; detail = console-output with `$ identify` metadata block + related Studies. Styling → prototype (ticket 17).
- [Prototype: Prints contact-sheet listing (+ detail page)](issues/15-prototype-prints-contact-sheet.md): Listing = contact-sheet grid A — uniform terminal-window tiles (filename + duration titlebar, `printer · material · #tags` caption), `$ ls prints/` filter row with `--material=`/`--printer=` chips. Detail = D — B's side-by-side layout with sticky left photo column + photo set, C's fact-sheet windows right (`specs` datasheet table, `models & notes` with `↗` links), B's maker-log timeline (dated entries, pink-dot failures). Prototype: `prototype/prints-prototype.html` on branch `prototype/homepage-look`.
- [Prototype: Soliloquy / Studies listings + detail pages](issues/16-prototype-writing-listings.md): Soliloquy listing = C (Date rail) — sticky month rail + timestamped entries (pink `[date · time]`, dim micro one-liners, inline image thumbs). Studies listing = E (Unframed editorial) — no window chrome; featured lead study + dated ledger rows with italic summaries. Soliloquy detail = C (Printout) — perforated single-entry view, `· · ·` EOF, `$ cd ../entry-NN` nav. Studies detail = C (Split + fact sheet) — unframed article, `$ identify` specs datasheet sidebar, related studies by project → tag fallback. Prototype: `prototype/writing-prototype.html` on branch `prototype/homepage-look`.
